# DATA_SCHEMA — 지식베이스 파일 설명서

## 원본 형식: CSV (추천)
**이유 한 줄: 엑셀에서 바로 열고 저장할 수 있고, 한 줄 = 한 항목이라 고친 곳이 눈에 잘 보이며, 파이썬 표준 라이브러리(`csv`)로 바로 읽힌다.**
JSON은 엑셀에서 채우기 어렵다. 필요하면 코드가 CSV를 읽어 JSON으로 바꿔 쓴다.

## 파일이 사는 곳
| 곳 | 폴더 | 내용 |
|---|---|---|
| GitHub | `samples/` | 가짜 회사 "한빛테크"의 가짜 데이터 |
| 실행 PC(회사) | `data/` | 실제 데이터. **GitHub에 올라가지 않음**(`.gitignore`) |

`config.py`의 `DATA_DIR`이 어느 폴더를 읽을지 정한다. 파일 이름과 열 이름은 두 폴더가 같아야 한다.

## 공통 규칙
- 첫 줄은 열 이름(영어 그대로 둔다). 둘째 줄부터 내용.
- **여러 값은 `|`(세로 막대)로 나눈다.** 예: `연차|반차|휴가 쓰`
- 칸 안에 쉼표(,)를 쓰지 않는다. 나열은 `·`을 쓴다.
- 키워드는 **두 글자 이상**. 한 글자(예: "차")는 너무 많이 걸린다.
- 키워드는 띄어쓰기를 무시하고 비교한다("차 쓰고" = "차쓰고").

## 엑셀에서 채우는 법
1. 엑셀에서 `samples/파일.csv`를 연다(글자가 깨지면: 데이터 → 텍스트/CSV에서 가져오기 → 파일 원본 `65001: UTF-8`).
2. **ID 열(`menu_id`, `menu_ids`, `answer_ids`)은 채우기 전에 열 전체를 선택 → 마우스 오른쪽 → 셀 서식 → 텍스트.** 안 하면 엑셀이 숫자 ID를 `1.23E+11`처럼 바꾸거나 앞자리 0을 지운다.
3. 가짜 내용을 지우고 실제 내용을 채운다. **열 순서와 열 이름은 바꾸지 않는다.**
4. 저장: 다른 이름으로 저장 → 파일 형식 **"CSV UTF-8(쉼표로 분리)"** → `data/` 폴더에 같은 이름으로.
5. `python check_data.py`(회사 PC에서는 `py check_data.py`)로 빈칸·중복·없는 메뉴 ID를 검사한다.

## 1. `menus.csv` — 메뉴 지도 (1층)
| 열 | 뜻 | 예시 | 채우는 법 |
|---|---|---|---|
| menu_id | 메뉴 고유 ID. 바로 열리는 주소를 만드는 열쇠 | `HB-3003` | 포털에서 메뉴를 열었을 때 주소에 있는 ID를 그대로 |
| menu_name | 포털에 보이는 메뉴 이름 | `법인카드 사용 신청` | 화면 그대로 |
| path | 메뉴까지 가는 길 | `출장·경비 > 경비 > 법인카드` | 상단 메뉴 > 중간 > 끝, `>`로 연결 |
| synonyms | 사람들이 실제로 쓰는 말 | `법인카드\|회사 카드\|카드 신청` | **가장 중요한 열.** 동료에게 "이거 뭐라고 불러?" 물어 3~6개 |
| description | 한 줄 설명 | `법인카드 사용을 신청합니다` | ~합니다 체, 30자 안쪽 |
| owner_dept | 담당 부서 | `재무팀` | |
| contact | 연락 방법 | `내선 1103` | 개인 이름 대신 부서 대표 번호 |

> 메뉴 지도에는 **신입·인턴 누구나 열 수 있는 메뉴**를 넣는다. 일부만 열 수 있으면 넣지 않거나 `description` 끝에 "(정규직만)"을 적는다. 권한이 따로 필요한 메뉴·기밀 메뉴는 넣지 않는다. 사내 AI와 함께 채우는 법: `docs/MAP_PROMPT.md`.
| last_checked | 마지막으로 링크를 확인한 날 | `2026-11-24` | 지도 관리용. YYYY-MM-DD |

## 2. `situations.csv` — 상황별 체크리스트 (2층)
한 줄 = 한 상황의 한 단계. 같은 상황은 같은 `situation_id`를 반복해 쓴다.

| 열 | 뜻 | 예시 | 채우는 법 |
|---|---|---|---|
| situation_id | 상황 번호 | `S02` | S01~S07 |
| situation_name | 상황 이름 | `손님 방문` | |
| trigger_words | 이 상황을 떠올리게 하는 말 | `손님\|방문객\|외부인` | 같은 상황 줄에는 똑같이 복사 |
| step_no | 할 일 순서 | `1` | 1부터. 사업장마다 다르면 같은 번호를 두 줄로 |
| step_title | 할 일 | `손님 출입 등록` | 짧게, 동사로 끝내기 |
| menu_id | 연결 메뉴 | `HB-2002` | `menus.csv`에 있는 ID만 |
| site | 사업장 | `전체` / `본사` / `연구소` | 모두 같으면 `전체` |
| owner_dept | 그 단계 담당 부서 | `총무팀` | |
| tip | 한 줄 도움말(선택) | `방문 하루 전까지` | 비워도 됨 |

상황 7개: S01 신규 입사 / S02 손님 방문 / S03 출장 / S04 근무지 이동 / S05 기숙사 / S06 식사 / S07 재충전

## 기록 파일 `logs/questions.csv` (실행 PC에서 저절로 생김, 손으로 만들지 않음)
| 열 | 뜻 |
|---|---|
| time | 시각 |
| screen | `main`(메인 큰 검색창, 규칙만) / `chat`(챗봇 창) |
| event | `질문` / `클릭`([열기]를 누름) |
| question | 질문(긴 숫자·전화·메일은 `[숫자]`·`[전화]`·`[메일]`로 가림) |
| answer_type | `answer`(찾음) / `to_chat`(메인이 못 찾아 챗봇으로 넘김) / `unknown`(챗봇이 거절, 선배에게 여쭤보기 문구) |
| source | `rule`(규칙) / `ai`(사내 AI) |
| menu_ids | 보여 준 메뉴 ID(클릭 줄은 누른 메뉴) |
| situations | 보여 준 상황 대시보드 |
| ai_reply | 사내 AI의 한마디 |
| llm_error | 사내 AI 오류(있을 때만) |
| ms | 응답 시간(밀리초) |

이름·사번·IP·컴퓨터 이름·세션은 없다. 요약: `python log_report.py`.

## 4. `synonyms.csv` — 동의어 사전
질문에 `word`가 있으면 `standard`를 질문 뒤에 **덧붙여** 다시 찾는다(바꿔 치우지 않음).

| 열 | 뜻 | 예시 |
|---|---|---|
| word | 사람들이 쓰는 말 | `법카` |
| standard | 지도에 있는 말 | `법인카드` |
| note | 메모(선택) | `줄임말` |

`menus.synonyms`와 차이: 메뉴 동의어는 "그 메뉴 하나"에만, 동의어 사전은 "모든 질문"에 쓰인다. 포털 검색 개선에도 그대로 줄 수 있는 자산이다.

## 5. `eval_questions.csv` — 정답셋
| 열 | 뜻 | 예시 |
|---|---|---|
| q_id | 번호 | `E01` (일상어) / `N01` (메뉴 이름) / `X01` (범위 밖) |
| q_type | 종류 | `일상어` / `메뉴이름` / `범위밖` |
| question | 질문 그대로 | `법카 어디서 신청해?` |
| answer_ids | 정답 메뉴 ID(여러 개면 `\|`) | `HB-3003`, 범위 밖(길잡이가 몰라서 선배에게 여쭤보기를 권해야 정답)은 `UNKNOWN` |
| note | 메모 | |

- **채점 규칙**: 정답 ID 중 하나라도 상위 3개 안에 있으면 성공.
- **일상어** = 길잡이가 이겨야 하는 곳, **메뉴이름** = 비겨도 되는 곳. 두 종류를 따로 센다.
- 실제 정답셋은 `data/`에서 **실제 질문을 들은 대로** 다시 쓴다(가짜 데이터는 정답에 맞춰 만든 것이라 점수가 높게 나온다).
