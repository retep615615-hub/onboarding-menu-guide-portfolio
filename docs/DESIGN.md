# DESIGN — 온보딩 메뉴 길잡이 (1쪽)

## 무엇을
사내 PC에서 여는 화면 하나. 맨 위 제목(외부 브랜드)은 설정 `APP_TITLE`(앞에 🌱).
- **메인 = 큰 검색창 + 상황 대시보드 카드**: 대시보드(신규 입사, 손님 방문, 출장 …)마다 **제목과 링크 버튼**만 있다. 큰 검색창은 **규칙으로만** 맞는 대시보드(또는 메뉴)를 찾아 앞에 강조한다. **AI는 쓰지 않는다.** 못 찾으면 오른쪽 아래 챗봇 창을 열어 같은 질문을 넘긴다.
- **오른쪽 아래 동그라미 💬 = AI 챗봇 창**: 화면 위에 작은 창(PIP처럼)으로 겹쳐 뜬다. 규칙 → (못 찾으면) 사내 AI가 **엄격하게**(확실할 때만) 메뉴 지도 안에서 고른다 → 그래도 없으면 답을 거절하고 "이 질문은 제가 아직 잘 몰라요. 부서 선배님께 편하게 여쭤보는 건 어떨까요?…". 창 이름은 설정 `CHAT_TITLE`.

길잡이는 **사내 PC 안에서만** 돈다. 신입이 사내 PC를 받기 전(입사 전)에 필요한 안내는 맡지 않는다.

## 왜
- **신입·인턴이 무엇을 가장 궁금해하는지 데이터로 안다.** 질문과 답을 익명으로 기록해, 못 찾은 질문·많이 묻는 주제·틀린 답을 찾아 지도와 온보딩 자료를 고친다. 이것이 이 챗봇을 쓰는 첫째 이유다.
- 포털에 메뉴 검색창은 이미 있다. 하지만 **메뉴 이름을 알아야** 찾을 수 있다. 사람들은 "법카 어디서 신청해?", "손님 와"처럼 **일상어**로 묻는다.
- 진짜 자산은 모델이 아니라 **메뉴 지도(데이터)**다. 모델은 바뀌어도 지도는 남는다.

## 누구를 위해
1. 신규입사자·**인턴**(사내 PC를 받은 뒤): 무엇을 어디서 하는지 모른다. 사람마다 열 수 있는 메뉴가 다를 수 있다.
2. 기존 직원: 가끔 하는 일(출장, 손님 맞이, 근무지 이동)의 메뉴를 잊는다.

## 구조: 3층 집
| 층 | 하는 일 | 어디서 | AI |
|---|---|---|---|
| 1층 메뉴 지도 검색 | 질문 → 동의어 펼치기 → 메뉴 점수 → 상위 3개 + 링크 | 메인·챗봇 | 안 씀 (즉시) |
| 2층 상황 대시보드 | 상황 7개 → 할 일 + 링크 + 담당 부서 | 메인·챗봇 | 안 씀 (즉시) |
| 3층 사내 AI | 1·2층이 못 찾았을 때만, 질문 + 메뉴 지도 목록을 사내 AI(OpenAI 호환 API)에 주고 **지도 안에서만**, **확실할 때만(sure=true)** 고르게 한다. 메뉴와 상관없거나 애매하면 거절. 지도에 없는 ID는 버린다 | **챗봇 창만** | 켜고 끌 수 있음. 꺼지거나 연결이 안 돼도 1·2층은 동작 |

- 지식베이스: 메뉴 지도 / 상황 대시보드 7개 / 동의어 사전 / 정답셋 (모두 CSV, `docs/DATA_SCHEMA.md`)
- 메뉴마다 고유 ID가 있고, `config.py`의 주소 틀에 ID를 끼워 **바로 열리는 주소**를 만든다.
- 상황 7개(일반명): 신규 입사 / 손님 방문 / 출장 / 근무지 이동 / 기숙사 / 식사 / 재충전
- 사내 AI는 벡터 DB·임베딩 없이 메뉴 지도를 그대로 읽는다(Ollama·AnythingLLM 없어도 된다).

## 화면 흐름
```
[메인]  🌱 제목 + 큰 검색창 + 예시 질문 + 🔒 수집 안내 + 상황 대시보드 카드(제목 + 링크 버튼, 처음부터 보임)
   └─ 큰 검색창 질문 → 규칙만:
        ① 맞는 대시보드 → 맨 앞에 초록 테두리로 강조, 나머지는 흐리게 ("전체 보기"로 되돌림)
        ② 대시보드는 없고 메뉴만 맞음 → 🔍 찾은 메뉴 카드
        ③ 둘 다 없음 → 💬 챗봇 창이 열리고 같은 질문을 챗봇에게 넘김
[💬 챗봇 창]  규칙(대시보드 순서·메뉴) → 사내 AI(엄격, 'AI 추천' 표시) → 거절: "이 질문은 제가 아직 잘 몰라요…"
```
- 화면 아래 고정 문구: "링크를 누르는 것은 여러분입니다. 길잡이는 아무것도 대신 신청하지 않습니다."
- 상태 표시: "질문 기록: 켬(익명) · 사내 AI: 켬/끔".
- **수집 안내**: 메인 검색창 아래와 챗봇 창 아래에 작은 글씨로 "🔒 이름·사번 없이 익명 저장, 개선·통계에만, 인턴십·인사 평가에 반영 안 됨" + [자세히]. 거슬리지 않게, 그러나 숨기지 않는다. 문구는 설정 `LOG_NOTICE`, `LOG_NOTICE_DETAIL`.

## 기록 (guide/qlog.py → logs/questions.csv, 요약은 log_report.py)
| 남기는 것 | 남기지 않는 것 |
|---|---|
| 시각, 화면(메인/챗봇 창), 질문(긴 숫자·전화·메일은 가림), 답 종류(찾음 / 챗봇으로 넘김 / 못 찾음), 찾은 방법(규칙/AI), 보여 준 메뉴·대시보드, AI 한마디·오류, 응답 시간, [열기]를 누른 메뉴 | 사번, 이름, IP, 컴퓨터 이름, 세션·쿠키, 질문과 클릭의 연결 |
- 보관: `LOG_KEEP_DAYS`(기본 90일) 지나면 길잡이를 켤 때 지운다.
- 관리자가 보는 법: `python log_report.py` → 못 찾은 질문(지도에 더할 후보), AI가 답한 질문(맞는지 확인 후 규칙으로 옮기기), AI 오류, 많이 묻는 것(5번 이상만).
- 여러 신입·인턴에게서 모으려면 길잡이가 **여러 PC에서 접속되는 곳**(서버 또는 허가받은 공유 PC)에서 돌아야 한다. 지금 설정(`HOST = 127.0.0.1`)은 그 PC 한 대에서만 열린다.

## 하지 않는 것
- 시스템 조작·자동 신청·로그인 대행 (읽기 전용. 링크를 누르는 건 사람)
- 개인정보 다루기 (사번·이름을 묻지도 저장하지도 않음)
- 관리자 할 일·알림, 날짜별 타임라인 (이 화면은 신입·인턴이 보고, 날짜에 얽매이지 않는다)
- 모르는 것을 지어내기. 메인 검색창은 AI를 쓰지 않고, 챗봇의 AI도 지도 안에서 확실할 때만 고른다. 못 찾으면 **선배와 직접 이야기하도록** 정중하게 권한다
- 기록을 사람 단위로 보거나 평가에 쓰기 (사람을 알아볼 정보를 남기지 않고, 인턴십·인사 평가·수습 판단에 쓰지 않는다. 화면에 그렇게 약속한다)
- 큰 설치 (표준 라이브러리 + HTML 파일 하나. 사내 AI 연결도 표준 라이브러리 `urllib`)
- **입사 전 신입 안내** (입사 서류, 첫 주 일정, 첫날 출근 장소·시간). 신입은 그때 사내 PC를 쓸 수 없다. 채용 담당이 보내는 **메일·문자 안내**가 맡는다(이 저장소 밖)

## 실행 환경 (실행 PC)
Python + 브라우저 + (선택) 사내 AI API. GPU 없는 일반 사무용 PC에서도 돈다.
화면은 외부 CDN·글꼴을 쓰지 않는다. 사내 AI를 꺼도 인터넷 없이 돌아간다.
